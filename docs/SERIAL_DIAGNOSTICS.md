# Наблюдение за узлами через Serial Monitor

Метка прошивки: `prototype-5mp-q8-scan15-sites-button-net-2026-10-26`.
Диагностика включена в Ethernet-профили `esp32s3cam_baku` и
`esp32s3cam_tovuz`, а также в общий Ethernet-сценарий. Отдельные старые
профили проверки оборудования не получают эту сводку.

Исправления от 26.10: [кнопка, задержки и восстановление IP](BUTTON_NETWORK_FIX.md).
Изменения состояния кнопки теперь печатаются в idle при каждом
подтверждённом переходе; полную сводку раз в 10 секунд ждать не нужно.

## Запуск

В PowerShell из папки `firmware`, заменив COM9 на порт вашей платы:

```powershell
$pio = "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe"
& $pio device list
& $pio run -e esp32s3cam_baku -t upload --upload-port COM9
& $pio device monitor -e esp32s3cam_baku --port COM9 --baud 115200 --dtr 0 --rts 0
```

После загрузки открыть монитор. Выход: Ctrl+C. Перед повторной прошивкой
закрыть монитор. Для повторной проверки LCD кнопка RST не требуется.
Для Товуза заменить профиль на `esp32s3cam_tovuz`.

После завершения setup появляется сводка `[diag]`, затем она повторяется
примерно раз в 10 секунд. Введите `STATUS` и нажмите Enter, чтобы получить
её сразу. Команда `HELP` печатает подсказку. `LCDCHECK` повторяет поиск и
инициализацию LCD без сброса процессора (подробности ниже). Команды и новые сообщения
диагностики работают через UART0/CH343 и встроенный USB, если этот USB
интерфейс доступен на плате. Они не инициируют проверку лица, съёмку,
сканирование штрихкода или запрос к AKS. Подробные строки драйвера `[lcd]`
идут через основной Serial: в текущей конфигурации это CH343/UART0.

## Проверка LCD без доступа к RST

Эта команда добавлена в версию `lcdcheck-2026-10-24`; старый ZIP
`serialdiag` знает только STATUS/HELP. Сначала загрузите новую прошивку.
Когда `active=NO`, в открытом мониторе введите:

```text
LCDCHECK
```

Нажмите Enter. Плата повторно запускает I2C0 на прежних GPIO47/3,
проверяет возврат Wire.begin и ищет настроенный адрес или автоматически
адреса PCF8574/PCF8574A. При отсутствии ответа заново печатается полный
блок `[lcd] --- разбор шины I2C ...`: отклики адресов и цифровые уровни
SDA/SCL. Это не измерение напряжения и не доказательство общей земли.

При успешном запуске LCD включается подсветка и на 5 секунд выводится
`LCD TEST OK` / `I2C connected`, затем возвращается дежурная надпись.
Ответ I2C всё равно не доказывает правильность видимых символов.
В конце выводится `[diag] LCDCHECK END result=READY` либо `NOT_READY`
и новая сводка. Команда не перезагружает ESP32 и не создаёт записей в AKS.
Если сейчас идёт проверка лица/штрихкода, ответ будет `LCDCHECK BUSY`;
команда не ставится в очередь, её нужно отправить снова после завершения.

## Что означает сводка

| Строка | Как читать |
|---|---|
| `BUTTON GPIO14=UP/DOWN; raw=HIGH/LOW; armed=YES/NO` | Подтверждённое состояние, текущий цифровой уровень и готовность к следующему нажатию. После загрузки/проверки требуется отпустить кнопку на 150 мс. Клик отмечается `CHECK_REQUEST accepted`; BOOT — другая кнопка. |
| `CAMERA init=OK/FAIL; state=...` | Последний результат инициализации и текущее состояние драйвера. Камера выключается между проверками штатно. `frames`, `jpeg`, `failures` показывают реальные результаты съёмки. |
| `GM67 evidence=NOT_CONFIRMED` | UART открыт, но физическая связь ещё не подтверждена. Отсутствие сканирования само по себе не означает неисправность. |
| `GM67 evidence=RX_BYTES_ONLY` | ESP32 обработала байты UART; полноценного принятого штрихкода ещё нет. |
| `GM67 evidence=COMMAND_ACK` | Сканер подтвердил настройку командами в Host Mode. В текущем пассивном режиме такого подтверждения может не быть. |
| `GM67 evidence=BARCODE_RX` | В разрешённом окне получен допустимый штрихкод. Это подтверждает приём от сканера, но не его приём команд. |
| `GM67 rx_processed / queued` | Байты, разобранные драйвером, и байты, ожидающие в UART. Диагностика их не читает и не забирает штрихкоды у сценария. |
| `LCD I2C_ACK=YES/NO/NOT_TESTED` | Свежий отклик адаптера по I2C. Если драйвер не готов, probe пропускается до его штатного восстановления (`NOT_TESTED; driver=NOT_READY`). Проверка адреса не изменяет текст. Отклик не подтверждает контраст, подсветку или правильность символов на самой панели. |
| `LCD WRITE_ACK / WRITE_FAILED` | Результат I2C-транзакций при выводе конкретного сообщения. Видимые символы всё равно проверяют глазами. |
| `W5500 SPI_VERSION=OK(0x04)/FAIL` | Чтение регистра версии W5500 по SPI, а не только сохранённый результат поиска при загрузке. Если библиотека изначально не нашла W5500, проверка сообщает FAIL. |
| `link=UP/DOWN/SLEEP; IP=...` | Состояние Ethernet. При ошибке SPI адрес помечен UNAVAILABLE. Живой линк не подтверждает маршрут до AKS. |
| `SERVER last_op; result; HTTP; age` | Последнее завершённое обращение, его результат и давность. Это сохранённое наблюдение, а не постоянный опрос AKS. `health-TCP-TLS` проверяет соединение, не авторизацию. `HTTP=0` означает отсутствие записанного HTTP-статуса. |
| `MEMORY heap; PSRAM` | Свободная память. Для текущей камеры около 5 Мп нужна PSRAM. |

## Общая цепочка одной проверки

После обычного нажатия кнопки:

```text
[diag] ... BUTTON: CHECK_REQUEST accepted
[diag][check=1] ... -> check-start
[diag][check=1] ... -> lcd-prompt
[diag][check=1] ... -> camera-capture
[diag][check=1] CAMERA frame=OK; 2560x1920; jpeg=... bytes
[diag][check=1] ... -> camera-to-aks-recognize
[diag][check=1] SERVER op=recognize; result=OK; HTTP=200
[diag][check=1] ... -> face-accepted-lcd
[diag][check=1] ... -> gm67-wait-barcode
[diag][check=1] GM67 window=BARCODE_RECEIVED; elapsed=... ms; code_length=...
[diag][check=1] ... -> gm67-to-aks-log-cargo
[diag][check=1] SERVER op=log_cargo; result=OK; HTTP=200
[diag][check=1] ... -> result-lcd
[diag][check=1] LCD: WRITE_ACK (check visible text on panel)
[diag][check=1] END result=SAVED; total=... ms; saved=1
```

Каждая смена этапа содержит uptime в миллисекундах, номер проверки и
длительность предыдущего этапа. Возможные итоги: `CAMERA_ERROR`,
`RECOGNIZE_ERROR`, `FACE_DENIED`, `SCANNER_MISSING`, `BARCODE_TIMEOUT`,
`CANCELED`, `RECORD_ERROR`, `NO_LINK`, `SAVED`. Отказ распознавания и отмена
не доказывают аппаратную неисправность. `SAVED` подтверждает запись по
ответу сервера; работоспособность LCD смотрят по отдельным строкам.

Для проверки всей цепочки нужны действительное распознавание лица и новый
штрихкод в течение 15 секунд. Диагностика не подменяет эти условия и не
создаёт тестовых записей. При тайм-ауте требуется новое нажатие и новое
распознавание, программной перезагрузки нет.

Диагностика работает в той же задаче, что и сценарий. Во время синхронного
запроса/съёмки периодические сводки и обработка команд ждут завершения
операции; последнее сообщение этапа показывает, какая операция выполняется.
Между проверками и во время ожидания штрихкода сводки продолжаются.
Дополнительная I2C-проверка ограничена существующим тайм-аутом драйвера.

Для проверки нужна загружающаяся плата с исправным питанием. При отсутствии
3,3 В или связи с загрузчиком эти сообщения не появятся до восстановления
запуска. Успешные сборки и тесты на ПК не заменяют проверку на оборудовании.
