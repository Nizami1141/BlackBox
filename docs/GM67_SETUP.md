# Настройка сканера GM67

## Временная проверка без команд сканеру

В Ethernet-прошивке сейчас включён `GM67_PASSIVE_UART_MODE=1` в
`firmware/include/config.h`. ESP32 не отправляет GM67 команды настройки,
запуска, остановки или сна. Сканер должен сам читать в Continuous mode;
прошивка очищает старый UART-буфер после распознавания лица и принимает
только новый штрихкод. Каждые 10 секунд Serial Monitor показывает число
принятых байт и состояние LCD/I²C.

Если сканер оставался в Host mode после предыдущего запуска, полностью
снимите питание именно с GM67 и подайте снова. Это возвращает временные
настройки, но не стирает параметры, ранее записанные в его память.
При `UART RX=0` и работающем луче проверьте TX GM67 → GPIO1, общую землю
и режим интерфейса. Если сканер не зажигает луч, пассивный тест не сможет
его запустить: нужно сначала установить Continuous mode средствами самого
сканера или восстановить управление командами (`GM67_PASSIVE_UART_MODE=0`).

Это диагностический режим, не режим строгого КПП: физически сканер может
читать код до опознания лица, хотя программа такие данные отбрасывает.

Источник — *GM67 Bar Code Reader Module User Manual, V1.3, Oct 2020*.
Ссылки на разделы даны по этому документу.

## 1. Заводские настройки (§3.1)

| Параметр | Значение |
|---|---|
| Интерфейс | TTL-232 (серийный) |
| Скорость | **9600** бод |
| Формат | 8 бит данных, без чётности, 1 стоп-бит |
| Режим чтения | **Continuous** (§4.2) — сканирует непрерывно сам |
| ACK/NAK | **разрешён** (§3.1.4) |
| Длительность одного скана | 3 с (§4.5) |
| Пауза между чтениями | 500 мс (§4.2.1) |
| Повтор того же кода | не раньше чем через 500 мс (§4.6) |

Нам нужно поменять три вещи из этого списка. Почему — ниже.

## 2. Что мы меняем и зачем

### 2.1 Continuous → **Host Mode**

Даташит, Приложение 6:

> «To start decoding and stop decoding the serial port command needs to be
> valid in host mode. Please switch to the host mode first.»

В режиме Continuous сканер светит и читает **всегда**. Для КПП это дыра:
можно отсканировать груз, не проходя распознавание лица. В Host Mode луч
включается только нашей командой `START_DECODE` — ровно после того, как
сервер подтвердил личность.

Команда: `07 C6 04 08 00 8A 08 FE 95`

### 2.2 Формат вывода → «оригинальные данные» (сырой ASCII)

По умолчанию сканер может отдавать данные SSI-пакетом `DECODE_DATA`, который
надо разбирать (заголовок, тип кода, контрольная сумма) и подтверждать
`CMD_ACK` на каждый код. Нам это не нужно — мы включаем сырой вывод:

Команда: `07 C6 04 08 00 EE 00 FE 39`  (параметр `0xEE` = `0x00`)

### 2.3 ACK/NAK → **запретить**

Иначе сканер после каждой отправки ждёт от ESP32 подтверждения и может
уйти в повтор.

Команда: `07 C6 04 08 00 9F 00 FE 88`  (параметр `0x9F` = `0x00`)

### 2.4 Терминатор → **CR LF**

Чтобы прошивка понимала, где кончился штрихкод.

Команда: `08 C6 04 08 00 F2 05 01 FE 2E`

## 3. Формат команды SSI и контрольная сумма

Кадр:

```
[LEN] [OPCODE] [SOURCE] [STATUS] [ ...данные... ] [CK_HI] [CK_LO]
```

* `LEN` — длина кадра **без** двух байт контрольной суммы, **включая** сам `LEN`
* `SOURCE` = `0x04` (хост)
* `STATUS` = `0x00` временно (до перезагрузки сканера) / `0x08` записать во флеш
* `CK` = **дополнение до двух** от суммы всех предыдущих байт:

```
CK = 0x10000 − (сумма байт)
```

Проверка на примере из даташита, `CMD_ACK = 04 D0 04 00 FF 28`:

```
сумма = 0x04 + 0xD0 + 0x04 + 0x00 = 0xD8
0x10000 − 0xD8 = 0xFF28   ✓ совпало
```

Для команд установки параметров есть ещё байт «beep code» = `0x00` сразу
после `STATUS`:

```
Однобайтный параметр:   [07] [C6] [04] [STATUS] [00] [PARAM]        [VALUE] [CK][CK]
Двухбайтный (0xF0..F2): [08] [C6] [04] [STATUS] [00] [PREFIX] [SUB] [VALUE] [CK][CK]
```

Обе формы реализованы в `firmware/src/gm67.cpp` как `sendParam1()` и
`sendParam2()`, контрольная сумма считается в коде — поэтому вы можете
добавить любой параметр из Таблицы 6-2 даташита, не считая её вручную.

## 4. Про сон

Приложение 6, первый абзац:

> «When the scanner is not working, it is in sleep mode. Under the sleep mode,
> need to wake up first, then send the effective command.
> (Wake up command: 0x00, 50 ms, then send the effective command)»

Поэтому `GM67::sendRaw()` **всегда** сначала шлёт один байт `0x00` и ждёт
50 мс. Если этого не делать, первая команда после паузы просто теряется —
это самая частая причина «сканер не реагирует на START_DECODE».

## 5. Два способа настроить сканер

### Способ А (рекомендуемый) — командами из прошивки

Ничего делать руками не надо: `scanner.configure()` в `setup()` шлёт все
четыре команды при каждом старте с флагом «временно» (`STATUS = 0x00`).

Один раз, если хотите зашить настройки в сканер навсегда, поставьте в
`config.h`:

```c
#define GM67_WRITE_CONFIG_TO_FLASH 1
```

прошейте, дождитесь загрузки, **верните обратно 0** и прошейте снова.
Флеш сканера не бесконечный — не пишите в него при каждом старте.

### Способ Б — сканированием QR-кодов настройки из даташита

Сканер настраивается собственными QR-кодами прямо из PDF. Порядок:

1. Стр. 7, §2.1 — **Factory default setting** (сброс к заводским)
2. Стр. 8, §3.1 — **TTL 232 Interface**
3. Стр. 8, §3.1.1 — **9600bps** (или 115200, если меняли)
4. Стр. 9, §3.1.4 — **Forbid ACK/NAK**
5. Стр. 12, §4.4 — **Host Mode**

Способ Б удобен для диагностики: если сканер молчит, сбросьте его на заводские
настройки этим QR-кодом и проверьте, идут ли вообще данные по UART в
Continuous-режиме.

## 6. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| В мониторе тишина, луч не горит | сканер спит | убедиться, что перед командой идёт `0x00` + 50 мс (уже в коде) |
| Луч горит всегда, не выключается | сканер в Continuous, не в Host Mode | проверить, дошла ли команда `8A 08`; сбросить на заводские и повторить |
| Приходят «кракозябры» | не совпал бод | сканер на 9600, а `GM67_BAUD` другой (или наоборот) |
| Код приходит, но склеивается со следующим | не включён терминатор CR LF | послать `08 C6 04 08 00 F2 05 01 FE 2E` |
| Приходят непечатные байты вокруг кода | остался SSI-пакетный режим | послать `07 C6 04 08 00 EE 00 FE 39` |
| Один и тот же код читается по 10 раз | «Time Interval For The Same Code» = 0 | §4.6.1, поставить `Delay 3s`; в Host Mode это обычно не проявляется |
| Сканер пищит и мигает, но данных нет | TX/RX перепутаны | поменять местами провода 2 и 3 |

Проверить сканер отдельно от ESP32 проще всего так: подключите его через
USB-UART переходник к ноутбуку, откройте терминал на 9600 8N1 и посканируйте
что-нибудь. Если в терминале появляются коды — сканер жив, проблема в
подключении к ESP32.

## 7. Какие штрихкоды читаются

По умолчанию (§1.7) **включены**: UPC/EAN, Code 128, GS1-128, ISBT-128,
Interleaved 2 of 5, Code 39, QR, Data Matrix, PDF417, Micro QR, Micro PDF417.

По умолчанию **выключены** (надо включать отдельно): Standard 2 of 5,
Industrial 2 of 5, Matrix 2 of 5, Code 32, Code 93, Code 11, Codabar,
PLESSEY, MSI, GS1 Databar, ITF-14, Aztec.

Если на грузах у вас **ITF-14** (частый формат для транспортной упаковки) —
он выключен, включите командой из Таблицы 6-2 или QR-кодом из §8.19.

Для маркировки грузов на КПП практичнее всего **Code 128** или **QR**:
оба включены по умолчанию, оба держат буквы и цифры, QR ещё и терпит
загрязнение наклейки.

## «Сканер сканирует, а в базу не отправляет»

Три причины, все найдены разом. Первые две — мои ошибки в фильтре, который
я же и добавил, когда чинил обратную беду (в журнал уезжал мусорный символ
`$`). Я перестраховался и перестрелял.

### 1. Окно тишины съедало настоящий код

Было: 150 мс после включения луча приходящим данным не верим. Рассуждение —
человек физически не успеет поднести штрихкод так быстро.

Успевает, потому что подносит **заранее**. Экран показывает «Kodu skan edin»
с задержкой (а пока он не работает — не показывает вовсе), и сотрудник
держит груз перед сканером с начала проверки. Луч вспыхивает, код читается
за 60–120 мс и попадает ровно в окно недоверия.

Промах при этом необратим. В Host Mode `START_DECODE` запускает ОДИН сеанс
чтения, и после удачного декода сканер останавливается сам. Выбросив
единственный декод, мы остаёмся с горящим лучом, который больше ничего
не прочитает. Снаружи: пискнуло, а записи нет.

Стало: `GM67_GUARD_MS 0`. Служебный кадр отличаем по содержимому, а не по
времени прихода — в нём нет ни буквы, ни цифры, а в номере груза они есть
всегда. Проверка живёт в `acceptable()` и продублирована на сервере
(`core/flow.py`, `_looks_like_barcode`).

### 2. Порог длины 4 отсекал короткие номера

Служебный кадр `04 D0 04 00 FF 28` даёт максимум **два** печатных символа,
значит порога 3 достаточно. Порог 4 сверх этого ничего не ловил, зато молча
съедал трёхсимвольный номер груза — и выглядело это как «штрихкод
не поднесли». Стало 3 и в прошивке (`GM67_MIN_CODE_LEN`), и на сервере
(`flow.min_barcode_len`).

### 3. Через 5 секунд сканер переставал читать

Отдельная поломка, не связанная с фильтром, и она бьёт даже когда всё
остальное исправно.

`START_DECODE` в Host Mode запускает один сеанс чтения. Сеанс кончается либо
удачным декодом, либо по длительности одиночного скана — параметр
`PX_SINGLE_SCAN`, у нас 5 секунд. А ждём мы штрихкод до 45 секунд. То есть
через пять секунд после `SCAN ON` сканер тихо переставал читать, и
оставшиеся сорок секунд плата ждала того, чего уже не могло произойти.

Стало: пока идёт ожидание, чтение перевзводится каждые `GM67_REARM_MS`
(2 секунды) — `rearmScanner()` в `main.cpp`. Перевзвод делается только когда
в приёмном тракте пусто: `startDecode()` чистит буфер и посреди приходящего
кода потерял бы его.

### Что смотреть в логе

На плате:

    [gm67] луч ВКЛЮЧЁН, жду штрихкод груза
    [gm67] прочитан код: "TRK-0001"
    [gm67] код #1 отправлен: "TRK-0001" (8 байт)

Если есть «прочитан», но нет «отправлен» — плата не на связи с сервером.
Если есть «отброшено…» — сработал фильтр, и строка в логе скажет, какой
именно. Если нет вообще ничего — данные не доходят по UART, включайте
`GM67_DEBUG_RAW 1`.

На сервере:

    [GATE-01] штрихкод 'TRK-0001' принят, проверка его ждёт

Если вместо этого «пришёл, но проверка сейчас НЕ идёт» — сканировали до
опознания лица либо уже после того, как проверка закончилась по таймауту.
Раньше такой код терялся молча, и это было неотличимо от неисправного
сканера.
