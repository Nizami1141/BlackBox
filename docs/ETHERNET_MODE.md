# Автономный пост: Ethernet вместо Bluetooth

Режим для границы. Bluetooth убран полностью, Wi-Fi не поднимается, плата
разговаривает с сервером по кабелю и умеет спать между проверками.

---

## 1. Что изменилось по существу

Не «поменяли провод», а поменяли, у кого инициатива.

| | Bluetooth (было) | Ethernet (стало) |
|---|---|---|
| Кто начинает проверку | сервер по кнопке на сайте | кнопка на самом посту |
| Кто командует | сервер: «снимай», «включи луч» | плата секвенсирует сама |
| Соединение | постоянное, пока пост жив | два коротких запроса и разрыв |
| Может ли пост спать | нет, канал надо держать | да, между проверками |
| Ноутбук рядом | обязателен | не нужен |

Постоянное соединение и сон несовместимы: спящая плата канал не удержит.
Поэтому в Ethernet-режиме инициативу забирает плата — нажали кнопку, она
проснулась, сходила двумя запросами, уснула обратно.

**Что при этом НЕ изменилось — и это главное.** Решения по-прежнему
принимает сервер:

* узнан человек или нет — решает сервер, у платы нет ни базы, ни модели;
* запись в журнал сервер делает **только** по действующему session token,
  а токен выдаётся исключительно после успешного опознания.

Поэтому даже подменённая прошивка не запишет «сотрудник проверил груз» без
реального опознания. Зажечь луч сканера она может когда угодно, но токена
у неё не будет, и сервер такой скан отвергнет. Тесты
`tests/test_device_api.py` проверяют ровно это.

Побочный эффект: кнопка «Проверить» на сайте для такого поста неактивна —
сервер ему не командует. На странице он показан как «автономный», и видно,
когда он последний раз выходил на связь.

## 2. Порядок включения

### На плате — `firmware/include/config.h`

**Уже выставлено — это текущее состояние файла, править ничего не нужно:**

```c
#define ENABLE_BLE       0        // Bluetooth убран полностью
#define ENABLE_ETH       1        // работаем по кабелю
#define ENABLE_BUTTON    1        // без кнопки проверку начать нечем
#define CHECKPOINT_MODE  1        // сканер в Host Mode

#define ETH_SERVER_HOST  "172.16.6.51"    // адрес ноутбука с сервером
#define ETH_SERVER_PORT  8000
#define ETH_API_KEY      "..."            // aks_api.api_key из config.yaml
#define CHECKPOINT_DEVICE_ID "GATE-01"

#define ETH_USE_STATIC   1                 // прямой кабель: DHCP взяться неоткуда
#define ETH_STATIC_IP    {172, 16, 6, 52}
#define ETH_GATEWAY      {172, 16, 6, 51}
#define ETH_SUBNET       {255, 255, 255, 0}
```

Несогласованные флаги ловятся при компиляции: включить BLE и Ethernet
одновременно или забыть кнопку не получится — сборка остановится
с внятным сообщением.

**`X-API-Key` — только ASCII.** Он уезжает в HTTP-заголовке; IP поста
сервер получает из TCP-соединения и по нему определяет `device_id`.

### На сервере — `server/config.yaml`

```yaml
devices:
  - device_id: "GATE-01"
    api_key: "beta-key-gate-01-change-me"
    link:
      type: "none"        # автономный: ходит сам, сервер им не командует
aks_api:
  api_key: "..."
  server_ip: "172.16.6.51"
  ip_devices:
    "172.16.6.52": "GATE-01"
```

`aks_api.api_key` должен совпасть с `ETH_API_KEY`. Адрес платы
`172.16.6.52` должен быть в `aks_api.ip_devices`: неверный ключ даёт 401,
неизвестный IP — 403.

### Адрес ноутбука: бета-тест на прямом кабеле

Сейчас настроено под прямое соединение плата ↔ ноутбук, без роутера
и коммутатора между ними. Раз роутера нет — нет и DHCP-сервера, адрес
выдавать некому, поэтому адреса заданы руками **с обеих сторон**:

| | Адрес | Маска |
|---|---|---|
| ESP32 + W5500 | 172.16.6.52 | 255.255.255.0 |
| ноутбук | 172.16.6.51 | 255.255.255.0 |

Плате адрес уже прописан в `config.h`. Ноутбуку надо задать свой:

```
Параметры → Сеть и Интернет → Ethernet → свойства адаптера
  → IP версии 4 (TCP/IPv4) → Свойства
  → Использовать следующий IP-адрес:
        IP-адрес       172.16.6.51
        Маска подсети  255.255.255.0
        Основной шлюз  ОСТАВИТЬ ПУСТЫМ
```

Или одной командой в PowerShell от администратора (имя адаптера
посмотреть в `Get-NetAdapter`):

```powershell
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 172.16.6.51 `
                 -PrefixLength 24
```

**Почему отдельная подсеть 172.16.6.x.** 192.168.1.x почти всегда
уже занята домашним Wi-Fi ноутбука. Два адаптера в одной подсети — и Windows
не может решить, в какой из них слать пакет; выглядит это как «пинг не
проходит, хотя всё воткнуто».

**Шлюз оставить пустым** — это не забывчивость. Шлюз нужен, чтобы выходить
за пределы своей подсети, а плата и ноутбук в одной. Прописанный
несуществующий шлюз на Ethernet-адаптере Windows считает основным
и ломает ноутбуку интернет через Wi-Fi.

Проверить, что связь есть, ещё до всякой прошивки:

```powershell
ping 172.16.6.52
```

Сервер уже слушает все интерфейсы (`host: "0.0.0.0"` в `config.yaml`),
отдельно ничего включать не надо. Но **брандмауэр Windows** при первом
запуске спросит, разрешить ли Python принимать соединения — разрешите
для частной сети. Если случайно запретили, запрос больше не появится,
и пост будет получать «сервер не отвечает» при живом кабеле. Разрешить
задним числом:

```powershell
New-NetFirewallRule -DisplayName "Checkpoint 8000" -Direction Inbound `
                    -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
```

### Когда дойдёте до роутера

Всё, что нужно поменять:

```c
#define ETH_USE_STATIC   0        // роутер раздаст адрес сам
#define ETH_SERVER_HOST  "..."    // адрес, который роутер выдал ноутбуку
```

Адрес ноутбука смотреть в `ipconfig`, строка «IPv4-адрес» того адаптера,
которым ноутбук воткнут в тот же роутер.

Оговорка про DHCP: адрес, выданный роутером ноутбуку, может измениться
после перезагрузки — и тогда пост будет стучаться в пустоту. Либо
закрепите адрес за ноутбуком в настройках роутера (DHCP reservation по
MAC), либо задайте ноутбуку статический адрес вне пула DHCP.

## 3. Питание и нагрев

Считать надо по потребителям, а не по ощущениям.

| Потребитель | Ток | Когда |
|---|---|---|
| GM67 сканер | ~180 мА | **круглосуточно**, сам не засыпает |
| W5500 | ~130 мА | постоянно, пока держит линк |
| OV5640 | ~100 мА | пока идёт XCLK — тоже круглосуточно |
| ESP32-S3 | 40–80 мА | на 240 МГц без радио |
| Подсветка LCD | ~25 мА | постоянно |

В покое набегало под 450 мА при том, что проверка бывает раз в несколько
минут. Почти вся эта мощность превращалась в тепло внутри одной коробки.

Что делает `POWER_MODE`:

| Режим | Что включено | Экономия |
|---|---|---|
| 0 | ничего, для отладки | — |
| **1** | сканер спит, камера выключена, CPU 80 МГц в покое | ~300 мА |
| 2 | то же + лёгкий сон CPU до нажатия кнопки | ещё ~40 мА |

По умолчанию **1**. Выигрыш почти весь, а отладка не страдает.

Режим 2 включайте, когда всё остальное уже работает: во время сна Serial
молчит, и в мониторе это выглядит как «плата умерла». Экран при этом
продолжает показывать своё — HD44780 держит картинку сам, без участия
процессора.

Самое крупное здесь — **сканер**, а не камера. GM67 ест 180 мА независимо
от того, горит луч или нет: спит он только по явной команде. Прошивка
усыпляет его сразу при загрузке и будит на время ожидания штрихкода.

W5500 сознательно не усыпляем: режим пониженного потребления у него есть,
но тогда теряется линк, а с ним и возможность узнать, что сервер жив.
Для поста это плохой размен.

### Порядок операций с частотой — не переставлять

```
power::active()  →  cam::wake()  →  снять  →  cam::sleep()  →  power::idle()
```

XCLK для камеры формирует блок LEDC, тактируемый от шины APB, а частота
APB меняется вместе с частотой процессора. Поднимете частоту после
включения камеры — XCLK уедет, и кадр испортится. Причём не отказом,
а «шумным» изображением, по которому распознавание честно ответит
«лицо не найдено», и вы будете искать проблему в модели.

## 5. Если не работает

Диагностика идёт снизу вверх — от провода к ключу.

**`Микросхема W5500 не найдена на шине SPI`**
Проводка. Чаще всего перепутаны MOSI и MISO: подписи `SI`/`SO` на модуле
означают вход и выход **модуля**, то есть `SI` идёт на MOSI платы, а `SO`
на MISO. Проверьте также SCS на GPIO 41 и питание 5 В.

**`Микросхема есть, но кабель не подключён`**
Светодиоды в разъёме RJ45 должны загораться сразу при подключении кабеля,
ещё до старта программы. Не горят — кабель, порт коммутатора или питание
модуля.

**`Кабель есть, но DHCP-сервера в сети нет`**
Если пост подключён напрямую к ноутбуку, DHCP там взяться неоткуда.
Ставьте `ETH_USE_STATIC 1` и задайте адреса вручную с обеих сторон.

**`сеть есть, но сервер молчит`**
Кабель и адрес в порядке, а сервера по указанному адресу нет. Проверьте:
запущен ли `app.py`, тот ли адрес в `ETH_SERVER_HOST`, не блокирует ли
брандмауэр Windows порт 8000 для частной сети.

**HTTP 401 в логе платы**
`ETH_API_KEY` не совпадает с `aks_api.api_key` в `server/config.yaml`.

**HTTP 403 в логе платы**
IP платы не зарегистрирован. Для стенда в `aks_api.ip_devices` должна быть
строка `"172.16.6.52": "GATE-01"`.

**Случайные перезагрузки во время отправки кадра**
Питание. W5500 в пике ест около 150 мА, и от вывода 3.3 В платы его
питать нельзя. Подавайте 5 В на вход модуля и поставьте электролит
100–470 мкФ поближе к нему.

**Кадр уходит, но всегда «лицо не найдено»**
Скорее всего частота процессора менялась при включённой камере и XCLK
уехал. Проверьте, что порядок в `checkpoint.cpp` не нарушен, или временно
поставьте `POWER_MODE 0`: если при этом всё заработает — дело именно в этом.
