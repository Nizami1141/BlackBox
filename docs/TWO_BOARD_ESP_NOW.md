# Две ESP32: камера отдельно, Ethernet и периферия отдельно

## Архитектура

```text
ESP32-S3 + OV5640
    │
    │ ESP-NOW, канал 1, без роутера и Интернета
    ▼
ESP32-WROOM-32 + кнопка + LCD + GM67 + W5500
    │
    │ Ethernet: 172.16.6.52 → 172.16.6.51:8000
    ▼
Ноутбук с сервером
```

Платы автоматически находят друг друга. MAC-адреса в код вписывать не
нужно. JPEG делится на блоки по 200 байт. Каждый блок подтверждается и при
потере передаётся повторно; собранное изображение проверяется CRC32.

Камера работает в QVGA (320×240), потому что обычная WROOM-32 обычно не
имеет PSRAM и должна уместить весь JPEG в своей внутренней памяти.

## Пины новой ESP32-WROOM-32

| Устройство | Сигнал | GPIO |
|---|---|---:|
| GM67 | TX сканера → RX ESP32 | 16 |
| GM67 | RX сканера ← TX ESP32 | 17 |
| LCD I2C | SDA | 32 |
| LCD I2C | SCL | 33 |
| W5500 | SCK | 14 |
| W5500 | MISO / SO | 12 |
| W5500 | MOSI / SI | 13 |
| W5500 | CS / SCS | 15 |
| Кнопка | сигнал, второй контакт на GND | 4 |

RST модуля W5500 в этой версии не управляется ESP32: используйте штатную
подтяжку модуля либо подтяните RST к 3.3 В. INT не подключается.

GPIO0, GPIO12 и GPIO15 — загрузочные выводы ESP32-WROOM-32. До окончательной
пайки обязательно проверьте холодный запуск с подключённым W5500. Если плата
не стартует, в первую очередь отключите провод MISO от GPIO12 и проверьте
уровни CS/MISO во время сброса.

## Питание

- Не соединяйте новую плату с узлом, из которого ранее шёл дым, пока узел не
  проверен на короткое замыкание.
- ESP32-S3 с камерой и ESP32-WROOM-32 со своей периферией лучше питать от
  отдельных исправных USB/5 В источников.
- Для ESP-NOW общий GND между двумя ESP32 не требуется: связь радиоканальная.
- Внутри узла WROOM земля ESP32, W5500, LCD и GM67 должна быть общей.
- Не подавайте 5 В непосредственно на GPIO ESP32. Для LCD с подтяжками к 5 В
  используйте двунаправленный преобразователь уровней I2C.

## Сеть ноутбука

Для отдельного кабеля W5500 ↔ ноутбук:

```text
Ноутбук:  172.16.6.51
W5500:    172.16.6.52
Маска:    255.255.255.0
Шлюз:     пусто
DNS:      пусто
Сервер:   0.0.0.0:8000
```

Не назначайте `172.16.6.52` сетевой карте Windows: этот адрес принадлежит
W5500. Ответ `TTL=128` на ping до прошивки W5500 обычно означает конфликт с
другим Windows-устройством в офисной сети.

## Сборка и прошивка

Из каталога `firmware`:

```powershell
# Старая ESP32-S3 с камерой; сейчас она подключена как COM14
pio run -e camera_node_s3 -t upload

# Узнайте COM новой WROOM: pio device list
# Затем замените COMx на найденный порт
pio run -e gateway_wroom -t upload --upload-port COMx
```

Монитор каждой платы:

```powershell
pio device monitor -p COM14 -b 115200
pio device monitor -p COMx  -b 115200
```

## Ожидаемая проверка

1. На обеих платах появляется `ESP-NOW готов`.
2. После включения второй платы появляется `найдена вторая плата` с её MAC.
3. На WROOM W5500 определяется по SPI и получает `172.16.6.52`.
4. Нажатие кнопки на GPIO4 создаёт `запрос кадра` на S3.
5. S3 пишет `кадр ... передан`, WROOM — `кадр 320x240`.
6. WROOM отправляет JPEG на `/api/recognize`.
7. Только после успешного распознавания включается GM67 и отправляется
   `/api/log_cargo`.

Если S3 не найдена, обе платы должны быть включены и находиться на небольшом
расстоянии. Роутер, Wi-Fi ноутбука и офисный Интернет для этого канала не
нужны.
