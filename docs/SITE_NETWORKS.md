# Баку, Товуз и окно штрихкода

Профили сборки: `esp32s3cam_baku`, `esp32s3cam_tovuz`.
Метка: `prototype-5mp-q8-scan15-sites-button-net-2026-10-26`.

## Адреса площадок

| Профиль сборки | ETH_SITE | IP | Маска | Шлюз |
|---|---|---|---|---|
| esp32s3cam_baku | 1 / ETH_SITE_BAKU | 172.16.5.193 | 255.255.0.0 | 172.16.0.1 |
| esp32s3cam_tovuz | 2 / ETH_SITE_TOVUZ | 172.20.204.193 | 255.255.255.0 | 172.20.204.1 |

Для обеих площадок DNS: **192.168.250.248**. Другие DNS по умолчанию
не используются. Все параметры подтверждены владельцем 23.10.2026 и
заданы в `firmware/include/config.h`.

Обычный `pio run` выбирает Баку для предварительного теста. Старое имя
`esp32s3cam` тоже выбирает Баку; для полевых условий следует явно выбрать
`esp32s3cam_tovuz`. Профиль прежней сети `ETH_SITE_CURRENT=0` сохранён как
отдельный вариант, но больше не выбирается по умолчанию.

Из терминала в папке `firmware` (заменить COM7 на фактический порт):

```powershell
$pio = "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe"
# Баку: предварительная проверка
& $pio run -e esp32s3cam_baku -t upload --upload-port COM7
& $pio device monitor -e esp32s3cam_baku -p COM7 -b 115200 --rts 0 --dtr 0

# Товуз: перед отправкой в поле закрыть монитор и загрузить этот профиль
& $pio run -e esp32s3cam_tovuz -t upload --upload-port COM7
& $pio device monitor -e esp32s3cam_tovuz -p COM7 -b 115200 --rts 0 --dtr 0
```

Перед прошивкой закрыть Serial Monitor. Выбор профиля без загрузки не
меняет программу на плате. При старте выводятся `[eth] сетевой профиль:
BAKU TEST` либо `TOVUZ FIELD`, затем фактические IP, маска, шлюз и DNS.

Профили работают по HTTPS с `aks.customs.gov.az:443`. Это два варианта
адреса одной платы для разных сетей, а не два одновременно назначенных IP.
Для каждой площадки надо подтвердить допуск её исходящего IP в AKS
(либо адреса после NAT). Автоматический выбор площадки не реализован.
Успешная сборка не подтверждает сетевую доступность AKS на месте установки.

## Штрихкод: максимум 15 секунд

Отсчёт начинается на этапе приёма нового штрихкода после успешного
опознания лица. `GM67_SCAN_WINDOW_MS=15000`. Если ответ AKS сообщает
меньший оставшийся срок токена, применяется меньшее окно.

Если код не получен вовремя или оператор отменил проверку:

1. Приёмный буфер GM67 очищается, завершённая проверка прекращается.
2. Накопленные нажатия кнопки отбрасываются. Если кнопка удерживается,
   её надо отпустить и нажать заново для следующей проверки.
3. Экран возвращается к приглашению нажать кнопку; следующая проверка
   снова требует нового распознавания лица и нового ответа AKS.

Код, полученный после дедлайна, не отправляется в `log_cargo`.
`ESP.restart()` не вызывается. Удалённый log_id не отменяется отдельным
запросом: в предоставленном API AKS такого метода нет; старая локальная
сессия больше не используется.

В активном Host Mode отправляется команда остановки декодирования.
В текущем `GM67_PASSIVE_UART_MODE=1` прошивка не управляет лучом: он может
продолжать светиться, но вне окна приёма код не привязывается к старому лицу.
Съёмка 5 Мп, качество JPEG 8 и поворот на 180 градусов сохранены.
