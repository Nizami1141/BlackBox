# Проверка GM67 на ESP32-S3

Эта прошивка проверяет **реальный сканер**, а не перемычку UART. Ранее
полученный `[PASS] UART1 received=5/5` проверил GPIO1/GPIO2 самой ESP32-S3;
`UART` с подключённым GM67 закономерно не получает эхо.

## Соединение

Полностью выключите питание, снимите перемычку GPIO2—GPIO1 и подключите:

| Контакт GM67 | Контакт ESP32-S3 |
|---|---|
| TX | GPIO1 (RX платы) |
| RX | GPIO2 (TX платы) |
| GND | GND (общая земля) |
| 5V | стабильные 5 В, не GPIO и не 3V3 |

Здесь речь именно о контактах **UART** сканера, не о его USB-разъёме.
Перед соединением GM67 TX с GPIO1 измерьте уровень TX относительно GND:
на вход ESP32-S3 нельзя подавать 5 В. Если TX поднимается выше 3.3 В,
используйте согласование уровней. Не соединяйте GPIO2 с GPIO1 перемычкой,
пока подключён сканер.

## Запуск

В каталоге `firmware` (при необходимости замените COM9 своим портом):

```powershell
pio run -e s3_gm67_check -t upload --upload-port COM9
python tools\gm67_command.py TEST --port COM9
```

Закройте Serial Monitor перед запуском Python-команды: COM-порт не может
одновременно использоваться двумя программами. Если нужен только просмотр
сообщений, откройте `pio device monitor -e s3_gm67_check -p COM9 -b 115200
--rts 0 --dtr 0` и отправьте `TEST` через монитор, если он принимает ввод.

Покажите сканеру штрихкод в течение 30 секунд. Тест выводит отдельно:

- `GM67 bidirectional UART ... PASS` — сканер ответил ACK на штатную команду;
- `GM67 barcode received` — на GPIO1 пришли данные прочитанного кода;
- `RESULT: PASS` — выполнены оба условия;
- `RESULT: PARTIAL` — подтверждена лишь одна сторона проверки;
- `RESULT: FAIL` — нет ни ответа на команду, ни кода.

Команды настройки посылаются со статусом **только до перезагрузки GM67**:
его Flash тест не переписывает. Отсутствие ACK само по себе не доказывает
поломку сканера: возможны неверный интерфейс USB/UART, питание, скорость
или отсутствие общей земли. Тест физически не запускается агентом — его
результат нужно получить на вашей плате.
