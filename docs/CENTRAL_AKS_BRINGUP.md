# Прямое подключение ESP32 к настоящему AKS

Основной маршрут: **ESP32-S3 → W5500 → https://aks.customs.gov.az/api**.
Сборка `esp32s3cam` включает `ETH_DIRECT_AKS=1` и `REGISTRY_ENABLED=0`.
Фото, проверка лица, живости, региона и запись штрихкода выполняются через AKS.
Локальный `server/app.py` для этого сценария запускать не нужно.

## Адрес и ключ

Основная сборка `esp32s3cam` задаёт `ETH_AKS_HTTP=0`: адрес
`aks.customs.gov.az`, порт 443, TLS включён. На USB-UART/CH343 (COM4)
используется сборка `esp32s3cam_uart` с тем же HTTPS API.
`ETH_API_KEY` содержит настоящий ключ из «esp32 - 08 10 2026.html».
Он передаётся в заголовке `X-API-Key`; диагностический вывод маскирует ключ.
Автоматического переключения адреса или перехода по redirect нет.
`esp32s3cam_https` — совместимое имя основной сборки.
Внутренний HTTP из HTML доступен только в профиле `esp32s3cam_http`;
текущий AKS перенаправляет HTTP-запросы (301), поэтому основной режим — HTTPS.
В режиме HTTPS разработки TLS шифрует соединение, но проверка сертификата отключена
(`ETH_TLS_INSECURE=1`). Для проверки сертификата задайте `ETH_TLS_INSECURE=0`
и `ETH_TLS_FINGERPRINT`, полученный у администратора AKS.

## Сеть и регионы

W5500 подключается к сети с доступом к AKS. Текущие параметры:

- IP платы: `172.16.6.52`;
- маска: `255.255.0.0`;
- шлюз: `172.16.0.1`;
- DNS: `192.168.250.248`.

Администратор сети должен подтвердить, что IP свободен и параметры подходят.
Прямой кабель к ноутбуку сам по себе маршрут в AKS не создаёт.
В AKS разрешают исходящий IP **платы**, который видит сервер; при NAT это может
быть адрес шлюза. Для разработки включают «Bütün Regionlar (Test)» для этого
IP в таблице «Mövcud İP - Region». Флаг допускает сотрудников разных регионов.
Неизвестное лицо и непройденная проверка живости по-прежнему дают `match: false`.

## Прошивка и проверка

Основная сборка использует встроенный USB-Serial/JTAG ESP32-S3
(`ARDUINO_USB_CDC_ON_BOOT=1`, сейчас COM3). Подключите кабель к встроенному
USB разъёму платы. Для прежнего USB-UART/CH343 сохранена отдельная сборка
`esp32s3cam_uart`.

Из папки `firmware/` выполните, заменив COM3 своим портом:

```powershell
pio device list
pio run -e esp32s3cam -t upload --upload-port COM3
pio device monitor -e esp32s3cam -p COM3 -b 115200 --rts 0 --dtr 0
```

При загрузке ожидается:

```text
[eth] режим: прямой AKS, API: https://aks.customs.gov.az:443/api
```

`TLS OK; авторизация ещё не проверена` подтверждает TLS-соединение. Ключ и IP
проверяются реальным запросом распознавания.

1. Сотрудник, зарегистрированный в AKS, встаёт перед камерой и один раз
   нажимает физическую кнопку.
2. Плата отправляет `POST /api/recognize`: multipart-поле `file` с JPEG и
   заголовок `X-API-Key`. Имя, фамилию и регион в запрос не добавляют.
3. При `match: true` AKS возвращает `user.first_name`, `user.last_name` и
   положительный `log_id`. Плата показывает имя и фамилию и включает сканер.
4. После сканирования плата отправляет `POST /api/log_cargo` с `log_id` и
   `cargo_barcode`. Ожидаются HTTP 200, `status: success`, «Yük qeyd edildi»
   на экране и запись в журнале AKS. Запрос создаёт реальную запись;
   используйте согласованный тестовый штрихкод.
5. Незарегистрированный человек должен получить `match: false`, отказ и
   возврат в ожидание без этапа записи штрихкода.

HTTP 401 — ключ не принят; HTTP 403 — IP отсутствует в whitelist;
ошибка DNS/TCP/TLS — проблема подключения до распознавания.
HTTP 301 означает, что сервер перенаправляет запрос вместо обработки API.
Если внутренний HTTP отвечает 301, администратору AKS нужно подтвердить
актуальный HTTP endpoint или исправить перенаправление; альтернативой
остаётся HTTPS. Прошивка не пересылает фото и ключ по произвольному redirect.

Двойное короткое нажатие кнопки с отпусканием в пределах 2 секунд вызывает
перезагрузку ESP. События фильтруются отдельной задачей даже во время HTTP:
требуются устойчивое нажатие и устойчивое отпускание, короткие импульсы
и удержание от 2 секунд исключаются из команды перезагрузки. События,
накопленные при инициализации, отбрасываются перед переходом в рабочий режим.

## Если AKS возвращает отказ для зарегистрированного человека

Строка `Uz tapilmadi` может быть запасным текстом прошивки при пустом
`faces`. Размер JPEG и HTTP 200 не доказывают, что лицо видно в кадре или
что AKS проверил нужный регион. Новая прошивка печатает `[eth] AKS response:`
и `faces_count` для точного разбора ответа.

Для просмотра именно отправленного кадра обновите и прошейте `Yusif` на
ноутбуке, к которому подключена плата. Закройте Serial Monitor, встаньте
перед камерой и из папки `firmware/` выполните:

```powershell
python tools/aks_capture_check.py --port COM3
```

Нужен Python с пакетом `pyserial` (он уже есть в Python PlatformIO).
При необходимости: `python -m pip install pyserial`.
Команда `DEBUG_CHECK` запускает один обычный запрос распознавания и
экспортирует через COM его JPEG. Фото и ответ сохраняются в
`aks_debug_photos/`. Запрос в AKS по-прежнему отправляет сама плата;
локального сервера в этом тесте нет. Если человек опознан, плата перейдёт
к обычному ожиданию штрихкода. Для диагностики фото сканирование не требуется.

Проверьте резкость, освещение, ориентацию и наличие одного лица на сохранённом
фото. Сопоставьте точный ответ AKS с записью сотрудника и настройками IP в AKS.
Для окончательной проверки серверной стороны администратору можно передать
этот же JPEG, время запроса и исходящий IP платы.

Для проверки только TLS через текущий COM4:

```powershell
python tools/aks_capture_check.py --port COM4 --tls-only
```

Плата устанавливает пять отдельных соединений с AKS и проверяет передачу
данных командой `GET /api/recognize` без авторизации. Она не снимает фото,
не передаёт API-ключ и не создаёт запись распознавания. HTTP 401/403/405
в таком тесте подтверждает получение ответа, а не успешную авторизацию. Ожидается
`TLS_END passed=5 total=5`. HTTP 403 при последующем распознавании означает
отдельную проблему whitelist, которую TLS-тест не проверяет.

TLS использует штатный mbedTLS ESP32 SDK поверх W5500. TCP-записи разбиты
на блоки не более 1024 байт, чтобы не превышать буфер Ethernet 2.0.2.
SPI для макетного соединения работает на 1 МГц; post-build environment
script `tools/w5500_spi_build.py` делает настройку воспроизводимой при
повторной установке проектной библиотеки Ethernet.
Приём TLS использует выровненный промежуточный буфер: SPI в ядре 2.x
обращается к данным блоками uint32_t, а смещения TLS могут быть невыровненными.
На подключённой плате COM4 две последовательные серии прошли успешно:
10 из 10 HTTPS-соединений и ответов HTTP 405 без передачи ключа или фото.
Это проверка транспорта; распознавание и разрешение IP проверяются отдельно.

## Мониторинг

В прямом режиме локальные Device Registry, heartbeat, `/selftest` и TXT
монитор ноутбука не участвуют в работе платы. Диагностика доступна в Serial
Monitor, результат прохода — в журнале AKS. Для мониторинга AKS нужен
согласованный endpoint: недокументированные heartbeat-запросы плата не отправляет.
Сборка `esp32s3cam_laptop` сохранена как отдельный стенд. Настройка
`central_aks.enabled` в `server/config.yaml` относится к нему и не меняет
прямое подключение `esp32s3cam`.
