# Подключение к настоящему AKS

`esp32.html` указывает центральный адрес `http://192.168.250.106/api`.
Ноутбук остаётся промежуточным узлом: ESP32 посылает JPEG и штрихкод на
локальный `app.py`, а тот пересылает их на AKS. Прямой кабель с ESP32 не
имеет маршрута к центральному адресу сам по себе.

## Сеть: два разных Ethernet-канала

Государственный Ethernet ноутбука должен иметь **свой назначенный ему** IP
и маршрут к `192.168.250.106`. Второй адаптер, к которому подключён W5500,
нужно держать в **другой подсети**, без шлюза и DNS. Нельзя назначать один и
тот же `172.16.6.51` обоим адаптерам: Windows может выбрать неверный
исходящий порт, и обмен перестанет работать.

После выдачи адреса администратором внесите фактические значения в:

* `firmware/include/config.h`: `ETH_STATIC_IP`, `ETH_SERVER_HOST`,
  `ETH_GATEWAY`, `ETH_SUBNET`;
* `server/config.yaml`: `aks_api.server_ip` и ключ `aks_api.ip_devices`.

Затем проверьте на ноутбуке маршрут и исходящий IP:

```powershell
Test-NetConnection 192.168.250.106 -Port 80 -InformationLevel Detailed
```

Центральный AKS видит **исходящий IP ноутбука в госсети**, а не IP W5500.
Именно этот исходящий адрес должен быть разрешён в его whitelist. Успешный
TCP-тест доказывает маршрут, но не подтверждает whitelist или API-ключ.

## Включение пересылки

Когда оба канала и whitelist подтверждены, установите в `server/config.yaml`:

```yaml
central_aks:
  enabled: true
  base_url: "http://192.168.250.106/api"
  timeout_seconds: 30
```

Перезапустите `app.py`. В `/api/v1/health` должно быть
`"recognition_source":"central_aks"`. При недоступном AKS сервер вернёт
ошибку: **локальное распознавание не подставляется вместо центрального**.
Ключ берётся из `aks_api.api_key`, но в логи не выводится.

Снимок и `X-API-Key` уходят по HTTP без шифрования, как указано в HTML.
Перед эксплуатацией согласуйте с владельцем AKS HTTPS или защищённый
сетевой канал и правила обработки биометрических данных.

`POST /api/esp/register` в центральном режиме пока возвращает 501, чтобы
не создавать человека только в локальной базе под видом центральной
регистрации. `GetInspectorsData` — другой SOAP-сервис; пока неизвестны
обязательный `Firm` и поля ответа, сверка списка инспекторов **не включена**.
Без этого этапа нельзя утверждать, что проверен допуск инспектора.
