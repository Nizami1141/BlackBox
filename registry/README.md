# Device Registry внутри cc2

Реестр собран из предоставленного `server.py` (API, SQLite, авторизация и
логи) и интерфейса `appproject-main`. Это отдельный процесс того же проекта
на порту **8001**. Основная система проверки лиц и штрихкодов остаётся на
порту **8000**.

Запускайте оба сервиса из корня проекта командой `python run_all.py` после
установки `server/requirements.txt` и моделей распознавания. Скрипт берёт
ключ `aks_api.api_key` из `server/config.yaml` и передаёт его реестру как
`DEVICE_API_KEY`. В прошивке реестр использует `ETH_API_KEY`.
Отдельный `ADMIN_API_KEY` необязателен: без него чтение
реестра разрешено только с самого ноутбука. База реестра создаётся в
`registry/devices.db`.

Плата с W5500 после загрузки регистрируется в реестре, затем раз в 30 секунд
отправляет heartbeat и накопленные события проверки. Основной сервер получает
свой heartbeat каждые 3 секунды. При недоступности реестра проверка сотрудника в
основной системе продолжает работать; регистрация повторяется позже.

Откройте `http://127.0.0.1:8000/` для поста и
`http://127.0.0.1:8001/` для устройств и логов. Настройки адреса реестра,
региона и имени поста находятся в `firmware/include/config.h`.

`examples/wifi_heartbeat` — исходный пример из appproject для **дополнительной
отдельной платы с Wi-Fi**. На основную ESP32-S3 его загружать не нужно:
функции реестра уже встроены в прошивку W5500 в `firmware/src/eth_link.cpp`.
