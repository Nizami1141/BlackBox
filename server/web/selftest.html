Тест ESP32 ↔ W5500 ↔ сервер

Страница делает запросы точно по контракту ESP32: multipart-кадр на /api/recognize, затем log_id и штрихкод на /api/log_cargo, оба с заголовком X-API-Key. Разница одна: кадр можно взять не с камеры поста.

Зачем это нужно. Когда пост отвечает NO_FACE, виноватых двое — сервер и кадр. Подсуньте заведомо хорошее фото: опознал — сервер исправен и разбираться надо с камерой; не опознал — дело в базе, пороге или модели, и камера ни при чём.

Последний кадр, который прислала плата. Живёт в памяти сервера до следующей проверки — на диск не пишется, это биометрия.

2. Устройство

Возьмите его из ETH_API_KEY в прошивке. Ошибка ключа даёт HTTP 401; IP вне белого списка — HTTP 403.

Отправится только после успешного опознания: без токена сервер такой скан отвергнет. Это и есть главная гарантия системы.

Что произошло по шагам

  • 1 Кадр выбран проверяется, что это действительно JPEG —
  • 2 API-ключ и IP приняты 401 — неверный X-API-Key, 403 — IP не в whitelist —
  • 3 Лицо найдено в кадре здесь и получается NO_FACE, если кадр негодный —
  • 4 Сотрудник опознан сравнение вектора с базой по порогу —
  • 5 Выдан log_id на сервере он связан с защищённой одноразовой сессией —
  • 6 Штрихкод записан в журнал сервер проверяет токен и привязку к посту —
